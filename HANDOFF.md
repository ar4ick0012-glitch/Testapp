## Решения и реализация v0.5

- Отдельная новая кампания `user://save_v05.json`: все герои 1 уровня, голые, пустой отряд. Старый `save2.json` не изменяется и не импортируется автоматически. Это выполняет просьбу сбросить персонажей для проверки нового старта без удаления прежнего прогресса.
- Игрок сам выбирает и расставляет бойцов. Доступны только воин, жрец, маг, охотник. Начальных мест3, после первой победы склепа4. Будущие классы в данных сохранены, их разблокировки убраны из обычной прогрессии; internal test_mode остаётся для стендов, UI «всё открыто» удалён.
- Вступление и `tutorial_text/target/active`, `acknowledge_intro` направляют через отряд → Нулевой поход → ручное надевание → склеп → материалы катакомб → ручной крафт оружия. Подсказка не выполняет действия за игрока.
- Нулевой поход: одна короткая обучающая локация, 3 обычных встречи и босс. По одному обычному оружию всем4 доступным классам только один раз (`training_claimed`). Надевание вручную.
- Первая победа склепа: участникам магическое оружие ilvl8 и нагрудник, защитнику ещё обычный щит. Следующие победы и другие встречи дают предметы с шансом. Склеп/обучение не дают углей. Первая обычная встреча катакомб выдаёт по углю атаки/стихий/защиты, дальше случайный дроп.
- Материал брони и профиль статов — разные поля `armor_type`/`profile`. `Items.generate(ilvl, rarity='', kind='', armor_type='', profile='')`; `Items.for_hero(hero,ilvl,rarity='',kind='')` подбирает разрешённый тип, понимает абстрактные weapon/offhand. `DB.can_use` учитывает материал/класс/ветку, не оптимальность стата. Старые вещи без armor_type остаются допустимы, исходные implicit не переписываются.
- Cloth mage/priest/warlock; leather/mail hunter/shaman; plate warrior/paladin. Воины и паладины пока не носят другие материалы. Priest staff либо mace/dagger+book/talisman; mage staff/sword/dagger с подходящим offhand. Staff теперь twohand, как greatsword. Замена на двуручное оружие учитывает снятие левой руки и вместимость сумки.
- Главное оружие несёт большую часть основного стата. STR main =3AP, off AGI=1AP; AGI main=3AP, off STR=1AP. STR даёт броню силовикам, танку со щитом блок. AGI — crit_attack/dodge. INT=3SP, мана/crit_spell/regen. Все коэффициенты Calc, пробные пользовательские числа. AP/SP усиливают умение через отдельные коэффициенты. Блок/уклонение — средняя физическая защита, не отдельные случайные события. У охотника ещё нет магической активки, SPD/мана от INT есть для дальнейшей системы.
- `Items.capacity`: ilvl<8=1prefix+1suffix; <28=2+2; >=28=3+3. Крафт и генерация соблюдают лимит. Повышение тира не превышает доступный ilvl.
- Уровни дают +0.5% базы умения/уровень, максимум15%; +1life/уровень, максимум30. Враги более чем на6 уровней ниже не дают XP; дополнительно xp_cap данжа. Уровень врага отделён от combat power (не умножать формулу старой силы на новые level7–12!). Диапазоны и ilvl в data/dungeons.json.
- UI gear фильтрует по совместимости; strength sword виден магу. Bulk sell продаёт только показанное. Backend хранилища пока общий cap60, старый overflow автопродажи сохранён; полностью отдельные контейнеры/лимиты не сделаны. Валюта общая.
- Крупная отдельная карточка класса над ветками. Талант нажатием только читается, отдельная «Выбрать» применяет; закрытые можно читать. Preview сохраняется после refresh. Панель лагеря прокручивается. Карта нумеруется с0, по наведению имя/уровень.
- Поддержка жреца переименована «Щит света»; механика честно остаётся +3%life/−2%taken, отдельного absorb-щита нет.
- Иконки ткани/кожи/кольчуги/лат различаются материалом/силуэтом. Боевые герои пока выглядят по классу/спеку, не по каждому предмету. Сохранены 39 оригинальных монстров и переходы между встречами из v0.4.

## Проверки и пределы выводов

Закреплённый Godot4.3: `/workspace/tools/godot-4.3/Godot_v4.3-stable_linux.x86_64`. Системный4.6.3 не использовать для совместимости. Тестовые XDG_DATA_HOME=/workspace/changes/v05/test-data, XDG_CONFIG_HOME=/workspace/.config, XDG_CACHE_HOME=/workspace/.cache. Setup helper `/workspace/tools/setup-idle-dungeon.sh` обновлён на Testapp; архив двигателя проверяется SHA512, уже совпадающий бинарник не перезаписывается во время работы.

Скрипты: onboarding42, stat43, gear24, formation30, item_card20, gear_filter21, tutorial_ui17, sprite161 = **358 проверок**. После изменений запускать релевантные, полные команды README. Все пишут только тестовые сейвы. craft_test — smoke без assert.

`balance_probe`160 сценариев: 120 стартовых и40 с настоящими cosmetic RNG-вызовами. Воин-защитник+светлый жрец+маг и такая же тройка с охотником, только учебное оружие: по20/20 побед склепа, без смертей. Средний минимальный HP20.3%/26.2%, лечение665.8/618.5, время86.2/88.5сек. С настоящим RNG отображения — тоже20/20 и0 смертей. В катакомбах обе стартовые тройки20/20 доходят до финального босса,0 побед; в третьем данже0 побед.

`formation_probe`80: обе правильные тройки20/20 побед; жрец впереди0/20 побед, в каждом случае погибает первым, затем вся команда. Это не универсальная гарантия для любого билда/состава.

`progression_probe`80: без лекаря0/20; arms-воин+жрец+маг20/20 без смертей в склепе. Четверо с гарантированной ilvl8 добычей ещё0/20 побед катакомб. Подготовленная четвёрка1уровня с разрешёнными ilvl18 вещами, здоровьем и coldres проходит20/20 без смертей: проверка достижимости билда, а не времени фарма/рыночной экономики.

Стенд `sim.gd -- 0.5 1`: за30 игровых минут активный автопилот прошёл обучение/склеп/катакомбы (22похода,8вайпов), остановился в культистах. Первые катакомбы≈0.21ч. Он имитирует ручной подбор, таланты и починку; не крафтит оптимальный билд. Нет обещания длительности полного прохождения и баланса всех8 данжей.

Реальные GL-снимки через Xvfb: `tools/capture_v05.gd`, отдельный XDG_DATA_HOME=/workspace/changes/v05/capture-data. Снимки после настоящего обучения/похода в docs/screenshots/v0.5. При съёмке подставляется только время симуляции, снаряжение не выдаётся через тестовый режим.
